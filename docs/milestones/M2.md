## How the subsystems were integrated

Routes obtain services through `app/api/dependencies.py`. Providers use the configured paths in `app/core/config.py` to build repositories, then inject repositories/services into the service that needs them. FastAPI shares dependencies within a request. Routes handle HTTP models, services enforce rules and repositories alone access JSON.

For `POST /checkout`:

1. `get_current_customer` verifies the token and loads the active caller.
2. The checkout route calls `CheckoutService.checkout`. It checks customer/cart/restaurant state and revalidates menu items through `MenuService.get_orderable_item`.
3. `price_lines` calculates the current lines and total with Decimal rounding.
4. `OrderRepository.create` saves the item/price/address snapshots to `orders.json`.
5. `CartService.mark_checked_out` and `CartRepository` close the source cart.
6. The API returns the saved order; `OrderService` later exposes its stored snapshot only to its authenticated owner.

`transaction(...)` holds the relevant repository locks around checks and writes, including checkout's carts/orders boundary. These are in-process locks; individual saves use atomic file replacement. They do not make two file replacements one crash-atomic transaction. Recovery logic handles an already-saved order whose source cart was not closed.

| JSON file | Stored records and relationships |
| --- | --- |
| `restaurants.json` | Restaurants with stable identifiers. |
| `menu_items.json` | Items linked to `restaurant_id`; current prices and availability. |
| `customers.json` | Profiles, active state, roles and salted password hashes. |
| `carts.json` | Customer/restaurant/item identifiers, quantities and active/checked-out state; no saved prices. |
| `orders.json` | Customer/restaurant/source-cart identifiers and fixed item/address/price/total snapshots. |

Ben's representative data includes a historical order and a filled cart. Chloe retains a historical order after deactivation. Ana starts without cart history. `test_representative_data_has_valid_relationships_and_totals` validates all five files. Ordinary feature tests use isolated temporary files and empty cart/order history; the seeded demo test explicitly restores the representative history.

## Known limitations

- JSON locking coordinates threads in **one server process**. Multiple workers need file locks or a database; separate JSON replacements are not a crash-atomic multi-file commit.
- Total equals subtotal. No payment processing, delivery fee, tax or order progression beyond `placed` is implemented.
- #51 stored-data consistency repairs are on current main through #104; branch results and older source snapshots must not be confused with the final reviewed release.
- Tokens expire. A new signing key invalidates old tokens; use a stable `SECRET_KEY` for restarts. No refresh-token or password-reset workflow is implemented.
- Browser/API integration permits the configured localhost/127.0.0.1 port-5500 origins.
